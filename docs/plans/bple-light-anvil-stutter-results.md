# BPLE 初始化异常与 Anvil 卡顿：结果

日期：2026-11-06。Unity 2022.2.23f1c1 / Windows 11。依据：F323–F335。

## 已保留的修复

1. **MaterialPropertyBlock 生命周期**：移除 BpleLightRuntime.Rendering.cs 的实例字段原生对象创建，改为 Awake 中创建，再注册相机渲染回调。没有屏蔽异常日志，也没有降低灯光效果/网格精度。
2. **接触对哈希冲突**：原来的 `(bodyA << 32) | bodyB` 使用 UInt64 默认高低位 XOR 哈希，相邻/网格编号导致严重冲突。实际 512 刚体堆叠的 1097 个接触对只有 43 个不同哈希值，最大同哈希组 255。改为完整 64 位 avalanche 哈希；精确键相等判定、接触顺序、累计冲量和代表点选择不变。
3. **同步/采样重复开销**：在已完成 ECS 依赖、独占步进的边界一次取得有界缓冲指针；缓存有限冲量事件标志；零角冲量不再重复查询/旋转连接坐标系。完整外步冲量仍然逐子步累计，零阈值、各轴阈值及非零角冲量判断保持不变。
4. **连接描述缓存**：缓存的是只含内联值的 Joint/ConstraintBlock3 的完整字节，不是自相对 collider blob。只有字节相同且原生连接/刚体有效、完整刚体句柄代次匹配时才复用。阈值、锚点、碰撞开关即使未增加版本号也能失效更新。
5. **销毁连接 ABI**：b3DestroyJoint 漏掉 wakeAttached 参数。两次独立原生休眠探测证明 false 保持休眠，true 唤醒两端。现在运行时删除传 1，整世界清理传 0，不再依赖未定义寄存器值。
6. **碰撞开关更新**：只销毁/重建连接不会为未移动的刚体代理重新生成碰撞对。碰撞开关变化时先调用原生 setter 通知 broadphase，再重建。原来唯一失败的碰撞开启用例，在不改变判据/输入后通过。

没有减少默认 4 子步或生产 4–16 档质量映射，没有恢复隐藏速度上限，没有弱化连接强度、动量/能量或几何回归容差。原来的质量/守恒修复继续保留。

## CPU 测量

每个场景：64 步预热、256 步测量，dt=0.02 s，关闭休眠；前后各两次独立私有 Unity 进程。以下是 **物理测试步 CPU P95**，不是屏幕帧时长或 GPU 性能。参考后端的同步运行模式不用于商业性能排名。

| Anvil 固定输入 | 修复前 P95（ms，A/B） | 修复后 P95（ms，A/B） | 保守结论 |
|---|---:|---:|---|
| 512 刚体接触堆叠 / 质量 8 | 9.673 / 12.277 | 5.182 / 4.938 | 超过 2.603 ms A/A 地板；保守收益 4.491 ms |
| 512 旋转部件网格 / 质量 8 | 5.421 / 4.793 | 3.762 / 2.605 | 超过 0.628 ms 地板；收益 1.031 ms |
| 1024 部件组合 / 质量 4 | 8.024 / 8.857 | 6.146 / 5.237 | 超过 0.833 ms 地板；收益 1.877 ms |
| 1024 部件组合 / 质量 8 | 10.371 / 13.903 | 8.332 / 7.286 | 数字下降，但 2.039 ms 保守收益低于 3.531 ms 地板，不能宣称该档总 P95 已通过 |
| 1024 部件无限阈值对照 / 质量 8 | 8.950 / 10.535 | 6.478 / 5.872 | 超过 1.585 ms 地板；收益 2.472 ms |

质量 8 组合的平均同步时间从 1.848–2.162 ms 降到 .572–.574 ms；事件导出从 .583–.645 ms 降到 .089–.094 ms。接触堆叠中“step 减原生 profile”的平均采样/interop余项从 4.937–5.414 ms 降到 .657–.690 ms。余项不是某一个 getter 的孤立耗时。

原来的严格“两档总 P95 均超过独立地板”的 check_performance.py 门禁仍保留并明确失败；没有把它放宽成全局 PASS。这个结果不承诺任意模型、极端碰撞量、固定步追赶或 GPU/渲染负载下完全不卡。

## 未保留的试验与测量边界

- 灯光预览 query/scratch/renderer 缓存试验虽通过语义几何/位置/颜色与增删/场景恢复检查，但未达到注册的 GC 证据条件，已回退；只保留必要的 Awake 修复。
- 当前 Unity Mono 的 GC.GetAllocatedBytesForCurrentThread 对显式 1 MiB 分配仍返回 0；Unity Mono-used 堆增长 1052672 字节。所有报告中的 0 thread-allocation 数值应视为 **指标不支持**，不是零分配证据。检查器禁止零对零推导 GC 优化。
- 原生 collector 饱和/纯读取探测通过，但原生 fullCounters 微基准为亚微秒级，未把它误归因为主要多毫秒卡顿，也没有盲目重写接触容量策略。
- Bridge 的 FindObjectsOfType 会漏掉 DontSave 单例；测试就绪判定改为读取真实单例/manager 状态。一次超时未重试写入，原 Play Mode 已恢复。
