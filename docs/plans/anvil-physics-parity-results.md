# AnvilPhysics 与 Unity / Havok 物理对照及修正

日期：2026-11-06。目标是同一部件几何、质量、受力和连接参数下的物理状态与强度相近，不要求不同求解器逐位或逐帧轨迹完全相同。

## 修正内容

1. **施力不再串部件。** 压缩上传列表原来存压缩槽号，而不是原动态体索引；改为保留实际部件索引。速度与已导出的值精确比较，不再吞掉每步 0.0005 m/s 的小增量。
2. **统一角速度坐标系。** Unity 的 AngularVelocity 在惯量主轴 / motion 空间，box3d 在世界空间。上传和回读都明确转换，质心与惯量方向保持 BodyFromMotion 的语义。
3. **质量和状态变更同步。** 复用刚体时同步质量、惯量、质心、重力系数和运动学类型；缩放、碰撞体地址或版本变化会正确重建。质量在形状创建后设置，以更新正确的形状尺度 / CCD 范围。
4. **正确读取碰撞体。** CompoundCollider.Child、ConvexHull、Mesh、Mesh.Section 含自相对指针，不能复制到栈上再读；改为在原 blob 上保留 ref。修正逐层复合偏移缩放，补充 Cylinder 凸包路径。
5. **连接不再偷偷丢失。** 同步关节时校验原生有效性、完整 body handle / generation、帧、约束、碰撞开关和版本。碰撞体重建后会重新建立连接。
6. **连接强度按整物理步冲量计算。** 不再把 MaxImpulse.x 当作原生标量力上限；按每轴绝对冲量、严格超限、零阈值和角冲量阈值检查，子步冲量累加后再判断。
7. **修正刚性与弹簧语义。** Unity 默认的巨大弹簧常数是其迭代刚性约束的编码，不是应直接传给原生的 74 kHz 弹簧。原生正 hertz 会在 relaxation 阶段继续施加偏置，曾使偏心连接链严重增能；默认固定连接改走原生 rigid weld。非默认弹簧仍保留自身参数。
8. **求解精度与积分顺序。** 默认四个原生子步；生产系统把 SolverIterationCount 映射到 4–16 子步。重力按 Unity 的顺序在整步开始前施加一次，阻尼在整步完成后施加一次；增细求解不会改变外力、阻尼和连接断裂强度。多子步接触也累加，不会丢掉只在前一子步出现的碰撞。
9. **睡眠 / 唤醒与对象映射。** 批量回读包含睡眠后的零速度，外部修改明确唤醒刚体。原生池 ID 不再被当成 PhysicsWorld 数组下标，新增 / 删除后射线和接触仍归属正确部件；同部件多个命中保留最近者。
10. **材质与隐藏限速。** 四种摩擦 / 弹性组合策略遵循 Unity 的优先级，默认弹性使用几何平均而不是原生最大值。CollisionResponse.None 保留查询但不传递碰撞动量。不再把有效自由线速度默认截断到 400 m/s，也不使用隐藏角速度截断掩盖约束错误。

部件目录和游戏连接强度常量没有调整；既有静态网格句柄释放、缓存查询及关闭重复 broadphase 刷新等工作保留。

## 对照结果

测试直接构造独立 PhysicsWorld，不切换或保存游戏场景、不改变玩家存档或当前后端。使用同样的碰撞体、质量、帧、输入冲量和 dt；Unity 与 Havok 都先验证确实在执行模拟。

两次最终独立进程采集 `final-a` / `final-b`：共 **301 项测量，297 项必需检查全部通过**；另外 4 项为明确标出的 Havok 参考偏差，仍显示失败，未计入通过。重复采集的最大数值差在各计量单位上均为 0。当前源码 / 原生库指纹为 `0ff8f1fbb2eef466f9d087c9e3f5242a5ff2928abba354aabaa0aad39d8fcba8`。

完整生产编辑器编译无错误；在该编辑器内取得并释放现有控制租约后运行同一独立物理 suite，也得到 **297/297 必需检查通过**，没有保存、切换场景或切换 Play Mode。最终原始报告保留在 `Tools/AnvilParity/reports/`。

## Havok 自身的参考偏差

当前项目的 Havok 托管 / 原生移植并非无误差 oracle：它吞掉每步 0.0005 m/s 的小速度增量，也吞掉本例 100:1 组合预期的 0.079208 m/s 低信号运动；全弹性碰撞案例有约 1.264954% 总动量损失。重力案例另有最多约 0.013457 m/s 的可重复数值差。

这些差异在报告中保留，未修改 Havok DLL、未放宽 Anvil / Unity 的动量守恒要求。100:1 的更强信号交叉控制仍为必需通过项。这里证明的是声明的状态 / 事件与数值容差，不是整个 Havok 移植实现的正确性。

## 重跑

在仓库根目录的 PowerShell 执行：

```powershell
& ./Tools/AnvilParity/Run-Private.ps1 -Label final-a
& ./Tools/AnvilParity/Run-Private.ps1 -Label final-b
python -X utf8 ./Tools/AnvilParity/check_report.py Logs/anvil-parity-final-a.json Logs/anvil-parity-final-b.json --baseline Tools/AnvilParity/reports/baseline-v4.json
```

脚本使用项目已有 Unity 路径、当前工作树物理源码、真实依赖和原生 DLL，在 D 盘的忽略目录构造小型测试项目；不会重启生产编辑器。C# 编译、缺测、非有限状态、指纹不符、重复采集不独立、未授权的参考豁免或超容差都会失败。

## 边界

- 不是每一种玩家构型或全部平台的穷举证明；没有改造或验证 Android / WebGL 的 Anvil 原生库。
- 原生尖凸包与 Unity 的 rounded / bevel 形状仍有边角差异；测试精确几何案例使用零 bevel。
- 原生公开质量 API 不支持真正的奇异惯量伪逆；部分无限惯量使用有限的大惯量近似（约 1e4 条件比），已验证自由轴连接响应，未宣称所有三维极端姿态都严格等价。
- Terrain、独立 Triangle / Quad、动态凹 Mesh 及非 fixed joint 的原生适配不在本轮完整支持范围；不能据此宣称这些类型等价。非支持关节会明确报错而不是偷偷焊死。
- 4–16 子步会增加求解 / 事件采样成本，未宣称性能提升。物理对照与接口、生命周期正确性是本轮验收口径。
