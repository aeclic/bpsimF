# 代理视角的难易：规范与个案

**断言**：难度与工期都是相对执行者的。代理主导的逆向/复刻没有人类工时预算，所以「人时」「FTE 年」「人眼看着简单」都不进决策。人觉得简单 ≠ 代理简单，反之亦然：对齐几张图对人是小事，代理没有手眼；反编译一千个函数对人是苦役，代理可以枚举后逐函数对拍。

## 0. 五问筛选器（选任务/方案前逐条回答）

1. **多项式时间有解吗？** 能否枚举 / 差分 / 反汇编得到，而不是「猜 + 看」？
2. **状态空间有限吗？** 输入、分支、配置列得全吗？
3. **反馈几秒？** 一条命令能否立刻给出 PASS/FAIL（重放、逐位比对、门禁）？
4. **判据直接吗？** 比调用序 / 字节 / 指令，还是比像素 / 波形 / 手感这类代理难判的量？
5. **能切片并行吗？** 各切片独立、共用一份判据、可交子代理集群同时跑？

任一条为否 → **先改造任务**（造 oracle / 缩状态空间 / 换判据 / 切片），再开工。

## 1. 分级

| 级 | 特征 | 做法 |
|---|---|---|
| **A 代理易** | 可枚举 + 可对拍 + 秒级反馈 | 批量做，切片并行（导表、逐函数 sim、绑定/脚本序列、坐标反推） |
| **B 中** | 可对拍但反馈分钟级 | 先建仪器，一次跑足样本（整机重放、游戏内采集、长时回归） |
| **C 代理难** | 需人眼/试玩，或状态空间巨大 | 只作**验收**，不作开发判据（像素、音频听感、手感/审美） |
| **D 不可判** | 没有 oracle、无法构造二值判据 | 明确标为不可自动化，别假装在测 |

**选路顺序**：① 先机械化（数据 / 反汇编 / 枚举），标注、手玩、目测排在后面；② 人类难但机械可解的优先（ABI、版本夹逼、逐函数替换、二进制差分）；③ 人类易但代理难的降级（标注、目测、试玩）放最后验收；④ 工期只用「反馈周期 × 切片数 ÷ 并行度」表达。

## 2. 开工前落表

任务写成五项 `(输入集, oracle, 判据, 单次反馈秒数, 并行度)`，写得出这五项才算定义好：

| 项 | 落点 |
|---|---|
| 输入集 | 语料/枚举清单在哪，总量多少 |
| oracle | 谁给参照答案（原版 exe / 存档 / 日志） |
| 判据 | 二值判据写在哪个工具、哪条命令 |
| 反馈秒数 | 单次跑完多少秒；失败能否定位到首个分歧 |
| 并行度 | 切片边界与共享接口；哪些部分要人眼、能否只放最后验收 |

五项写不出 = 任务没定义好，不是「难」。

## 3. 个案：标注 vs 从数据反推（人对易，代理对易的另一条路）

- 人对：把界面元素在截图上的位置逐个标出来，按天算。
- 代理实际：资源文件里本来就有每个元素的坐标字段；与截图检出的元素中心做最小二乘，得到设计坐标到截图像素的映射，再用一条独立标签交叉校验。标注工具还没找到，坐标已经能用了。
- 规则：**能用数据推出的，就用数据推**；标注只在没有数据来源、且误差可接受时做。

## 4. 个案：反编译 vs 逐函数对拍（人对难，代理对易）

- 人对：一万行反汇编、调用约定、类布局，按天算。
- 代理实际：导出函数表 → 候选源码用同工具链编出来 → 按指令序算逐函数相似度 → 扫修订号找跳变点；残差再用补丁复原到归零。工作量单位是「切片数 × 反馈秒数」，不是人时。
- 规则：**人类难但机械可解的任务优先**，它们是代理的主场。

## 5. 个案：目测渲染 vs 逐 draw 对拍（人对易，代理对难）

- 人对：看一眼界面，知道哪里歪了，改了再看。
- 代理实际：像素受 DPI / 过滤 / 前台窗口 / 时机干扰，A/A 自己都不稳定；改成逐绘制调用比 bbox/UV/纹理后，判据变成二值、秒级。
- 规则：**C 级（大状态空间 / 需人眼）只作验收**；开发期一律换成调用序 / 字节 / 指令级判据。

## 6. 个案：人时估算作废

- 旧口径：按函数粒度估出一个人时区间，再按人排期。
- 新口径：按 §2 的五项排期；工期 = 反馈周期 × 切片数 ÷ 并行度，人时表不参与排期。

## 7. 个案：人玩 vs 进程内记录

- 人对：一关一关玩、看日志、数对象，且受失焦暂停影响。
- 代理实际：进程内挂 thunk 记录，单进程一次采齐全量；与另一路探测逐项比对，剩下的差异用注入事件复现。
- 规则：把「人点一遍」换成「进程内记录一次」，单位从小时降到分钟。
