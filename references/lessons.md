# 个案库：症状 → 机制 → 规则

症状列写成**你脑子里闪过的那句话**：开工前与收尾各扫一遍，归因卡住时按分区对号。规范在 `SKILL.md`，仪器做法在 `instruments.md`。

## A. 判据与口径

| 症状 | 机制 | 规则 |
|---|---|---|
| 「一致率 99%，剩下算噪声」 | 均值/计数掩盖第一条错 | 只认**首个分歧**（step / 字段 / 双方取值）；后面全是垃圾 |
| 「整段相关 0.96，说明有差异」 | 整段均值掩盖分段 | 口径是**分窗 + 每窗最佳 lag**；只报整段等于误报 |
| 「超差个数涨了，说明在发散」 | 个数随场景活动量变化 | 归一化成幅度（`\|Δ\|/容差`）再看十分位；个数与幅度会给出相反结论 |
| 「波形 corr=0.9999，等于逐位一致」 | 中间隔着共享模式重采样与混音 | 输出重合 ≠ 内部逐位；写清「没证明的是哪一层」 |
| 「所有用例全绿，说明对齐了」 | 覆盖度 ≠ 等价性 | 逐例看 A/A 地板与首个分歧；最难的边界用例才是全部价值 |
| 「两个实现互相比对就够了」 | 双后端互比是循环论证 | 判据必须对**原版/oracle**，容差写进语料 |

## B. 因果与顺序

| 症状 | 机制 | 规则 |
|---|---|---|
| 「接触没了 / 对象丢了，所以物理才偏」 | 同一步内按阶段排序（更新接触 → 求解 → 积分 → 提交 AABB/broadphase）；后发生的是被解释项 | 按**阶段顺序**判因果，不按观察顺序；先找更早的那次子步 |
| 「删掉的对象还在表里，反正没报错」 | 簿记只增不减，会 dump 已释放内存 | 每类簿记配生命周期断言：删除事件是否也减少了计数 |

## C. 坐标系与单位

| 症状 | 机制 | 规则 |
|---|---|---|
| 「坐标/比例算出来挺合理」 | 被测进程 DPI-unaware，被系统放大；抓图是物理像素、被测逻辑是另一套尺寸 | 单位与坐标系写进仪器用法；比例按**抓图尺寸**算；DPI 感知先 `SetProcessDpiAwarenessContext(-4)` |
| 「覆盖率报 95%，库层已收敛」 | 分子在候选坐标系、分母在目标坐标系 | 跨坐标系计数写清分子/分母 + 一个**会崩的对照**（放到不可能匹配的位置应掉到 0） |

## D. 布局与常量

| 症状 | 机制 | 规则 |
|---|---|---|
| 「反编译里偏移是 +28，照着写」 | 布局是 L1 级猜，猜错不报错、只产出可信但错误的对照表 | `offsetof` 或「置值读回」实测：逐字段置值再读回 |
| 「常量在二进制里搜不到，说明原版没这个钳位」 | 钳位可能按 `dt` 归一化、运行时算（`0.5π/dt`），常量不在 `.rdata` | 改做**映射实验**：扫输入找饱和点，再变 `dt` 看饱和点是否移动——移动=每步量钳位，不动=常数钳位 |
| 「某字段恰好是 50π / 250 / 整千」 | 值 × `dt` 可能是漂亮数 | 先做一次乘除（-157.0796 × 0.01 = -0.5π ⇒ 每步最大旋转/平移的钳位特征值） |
| 「只测了孤立对象，可以下结论」 | 同一公式放在求解前/后，孤立场景结果相同，带交互才分开 | 受控实验要**同时覆盖孤立与带交互**两种场景 |
| 「两版产物行为不同，直接读反汇编」 | 有几项几十秒能验证的低成本项命中率最高 | 先按序排除：编译期常量折叠（`const` → `#define`）、池大小常量、默认构造是否清零、`/fp:` 开关、优化等级 |

## E. 驱动、自动化与状态判定

| 症状 | 机制 | 规则 |
|---|---|---|
| 「点了没反应，说明按钮坏了」 | 驱动通道不支撑（合成消息不触发，真实输入同坐标立刻生效） | 先做**阳性对照**（已知必然生效的最小动作），再谈被测对象 |
| 「定时点击落在启动动画里，不是主菜单」 | 启动动画/加载期占掉几十秒，任何固定延时都落空 | 先做状态判定（画面锚点/状态机），判定不出来时显式返回 `unknown` |
| 「悬停高亮了，点击应该也生效」 | 输入按帧轮询；瞬时 down/up 落在两帧之间，位置对也无效 | 按下保持 ≥150 ms 再抬起；悬停只证明坐标对，不证明按下被采样 |
| 「脚本跑两次结果一样，就是确定性输入」 | 只证明可重复，不证明可复现任意输入 | 要**录下输入再重放**才叫 harness；时序一改，结论就变 |
| 「游戏自己退了 / 崩了」 | 可能是探针超时清理把 debuggee 杀了 | 先查退出路径：超时 job 的强制结束、探针 `finally` 清理；排除仪器再说被测对象 |
| 「API 返回成功，值就是 0」 | 绑定未声明 `restype/argtypes`，64 位值被截成 int | 两个系统 API 双双恒 0（一个让 CPU 永远 0%、一个让 DPI 永远 unaware）；恒 0 / 恒空先怀疑绑定声明 |

## F. 环境与替身

| 症状 | 机制 | 规则 |
|---|---|---|
| 「第二个实例迟迟不出窗」 | 单实例限制；测到的是残留状态 | 探测前清残留实例/占用；单实例行为本身记 `待证` |
| 「环回录音自比，相关系数低得可疑」 | 别的进程占着声卡 | 独占设备先确认空闲 |
| 「自建那份和原版一样，能当参照了」 | 替身的等价性要另证 | 先过可观测面门禁：可观测量逐字段 `diffs=0` 之后才有资格当对照 |
| 「差异只剩一点点，记成已知偏差收工」 | 非代码输入也能改行为（PE 子系统版本、manifest、DPI 上下文） | 先追非代码输入再改代码：子系统版本过低会触发旧式非客户区度量 |

## G. 同源不同物

| 症状 | 机制 | 规则 |
|---|---|---|
| 「两棵树源码看起来一样」 | 头文件常量、宏、折叠、包含顺序都能改产物 | **逐文件二分替换**：每轮换一半、重编、重跑判据；收敛到单文件再看 diff，且 diff 的差异可能全无行为影响（真凶常是一个常量里的乘数） |
| 「逐单元百分比单调漂移，找不出哪一版」 | 相似度对重定位敏感，漂移把跳变点糊掉了 | **版本夹逼**：口径先钉死（与重定位无关的逐函数指令序）；扫修订号找**跳变点**，不看单调漂移 |
| 「夹逼扫完都没有跳变」 | 原版带本地补丁或来自别的分支 | 看残差**是否聚簇**（同文件/同主题）；聚簇 = 本地补丁，按反汇编复原成补丁，判据必须是**残差归零** |
| 「残差只剩十几个函数，逐个重写掉」 | 过度拟合 | 留**负例**：语料里必须有一个必须保持不同的成员 |
| 「无符号二进制里按 IDA 的函数边界算尺寸」 | 相邻函数会被并成一个 | 用「16 B 对齐 + 前导零填充」重新切目标函数后再比 |

## H. 迭代速度

| 症状 | 机制 | 规则 |
|---|---|---|
| 「工具能出反编译，迭代就快了」 | 生成侧早已不是瓶颈 | 迭代速度 ≈ **一次探测砍掉几个假设**；乘数按 ROI 排：判据机器可判 > 内部状态可见 > 结论可重放 |
| 「得换个更硬的仪器才能继续」 | 仪器成本可能超过它要回答的问题 | 先算问题值不值；换尺度往往三行代码解决（屏幕定时采样 > 上调试器拿一个定时器参数） |
| 「上游开源了，可以直接抄」 | 开源只降低猜布局成本 | **不提供等价性**：先对导出名/序号，再逐函数比行为 |
