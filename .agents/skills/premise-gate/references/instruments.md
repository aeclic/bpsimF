# 仪器（instrument）手册

一次性探测回答一个问题；**仪器**让同类问题以后都变便宜（差分 harness、转发/代理层、抓包器、布局探针、重放语料）。它和原型的区别：**别人能重跑**。

本文件是造/改仪器、以及报结论之前的清单。规则主干在 `SKILL.md`；个案机制在 `lessons.md`。

## 0. 一台仪器合格的定义

进 `tools/` 时，docstring 必须写明四件事，缺一件就不算仪器：

1. **命令**：怎么跑（输入路径 / 环境变量 / 前置目录）。
2. **判据**：PASS/FAIL 或期望输出（阈值、首个分歧）。
3. **覆盖边界**：它**看不见**什么。
4. **失效条件**：依赖哪个版本/布局/接口；上游一变即置 `过期`。**仪器失效比结论过期更危险**——它还在跑、还在输出，看起来一切正常。

规模超过一次会话能审完的代码就不算探测：拆成「最小可判真假」的一半先跑。

## 0.1 常量表生成器（从 oracle 录制生成代码常量）

适用：被测系统的构造常量是**计算值**（π 的倍数、1/128 网格、累加结果）。手抄十进制必漂 1e-5 级，而判据容差常在 1e-6。

纪律：

- 通过 oracle 轨迹把「调用」与「产物」对齐，按 (调用, style/变体) 聚合；先做**同键逐位一致**检查，不一致就拒绝生成并报出分歧的输入——不一致往往意味着结构里有栈残渣/未初始化字段。
- 生成物入仓，头部写「由 <工具> 生成，勿手改」；生成器带 `--check`，判据是**与仓库文件逐字节相同**，不是「能打印」。
- 生成器不给自己打分：判据仍是下游差额对拍（首个分歧 / 总数=0），生成器只负责把常量变成可重放的产物。

## 0.2 入口探针：把「从未执行」变成可判

适用：覆盖 / 死代码 claim，而现有仪器只 patch 直接调用点（Lua VM、虚表、函数指针全漏）。

命令：目标清单 → `gen_targets`（逐条定序言长度 + 生成 patch 表）→ 编 DLL → 注入器/代理装载 → 按周期把 raw counters 落盘 → 报告脚本映射回 VA。

做法：每个目标函数入口写 `jmp stub`；stub 内 `lock inc dword [counter]` → 重放被覆盖的序言字节 → `jmp target+L`。stub 里不加 `pushfd`：ESP 必须保持入口值（序言可能有 `[esp+4]` 取参），flags 不是调用约定输入。

判据：`installed=N failed=0`；阳性对照 ≥3 个必然执行的入口 `hit > 0`；同一进程两跑的 `hit > 0` 集合相同（计数随帧率浮动，判据取集合）。

覆盖边界：只覆盖目标表；序言含相对跳转、长度 >24 B、或存在 `(target, target+L)` 内部入口 → 生成器跳过；1 字节 nullsub 无法挂桩；安装前已执行的调用不计。

失效条件：目标二进制换版（全部 VA 失效）、ASLR / 非固定 ImageBase、patch 字节不是完整序言。

## 0.3 合成契约探针（synthetic contract）

适用：语料有**结构盲区**——采集层过滤（例：只读 getter 占日志 ~60%，默认丢弃）、宿主从未调用的入口。录制只能证明被观测到的调用，不能给未观测入口上判据。

命令：两侧各一子进程（崩了算失败，不毁会话）→ 固定序列 → 输出 `steps` 与 `exported=N/M` → 逐项对比；退出码 0 = 一致。

做法：

- **每入口至少一次**：从导出表/符号表取全集，序列里每个名字都要点到；覆盖集合进输出，缺一个就 FAIL。
- **指针比符号**（world/body/shape/joint 的注册名），不比地址；浮点给固定相对容差，整数/字符串精确。
- **A/A + 负例**：同一实现两次必须 0 差；再把一个入口的机器码改成固定返回值（按 **PE/ELF 导出表**查地址——旁路 CSV 的 rva 可能偏），探针必须报差。
- **返回类型按真身读**：`bool` 只写 `AL`，按 int 读会把 EAX 高位垃圾当值——这类导出只比低字节。
- **签名/布局没有第二来源时**：逐字节/逐参数置 1 + 最小可崩调用定槽位，再用反汇编确认；「跑通」不等于对。
- **步进场景要干净**：多个关节叠在同一对 body 上是病态约束（oracle 会出 NaN）；物理/回调片段另起简单场景。

覆盖边界：只覆盖 API 层（返回值/出参/对象类型/状态回读/回调是否触发），不含真实时序；与录制互补。

失效条件：导出表增删、宿主可见结构布局改动、固定序列里的对象生命周期顺序变化。

## 1. 自证清单

仪器自己错时报出的"目标缺陷"是它自己的缺陷，而且**不报错、只给结论**。所以自证写进流程，不靠运气。

| # | 自证项 | 判据 | 失败症状 |
|---|---|---|---|
| I1 | **A/A 地板** | 同一份输入、同一个 oracle 跑两遍，差值就是地板；任何"有差异"必须显著高于它 | 把末位噪声写成缺陷 |
| I2 | **oracle 自检（含覆盖自证）** | 两件事都要：① 把真实序列重放给 oracle 自己，差异不≈0 就弃用该仪器；② 日志里必须出现被测阶段的标记（init 段 / 首 step / ≥N 个对象）。缺 ② 时，「差异」先归因为「oracle 没跑到」 | 地板无穷大 ≠ 差异很大；把「录制没跑到被测阶段」当成目标缺陷 |
| I3 | **计数也要 A/A** | 计数类判据先让 oracle 跑同一份输入，量出地板 | 地板内的计数被当成证据 |
| I4 | **自证不能循环** | 拿"上一轮跑出来的数"复现自己只证明确定性；必须配**测前答案已知**的对照 | bug 被原样复现一次，然后写进台账 |
| I5 | **保真度** | 配对是否 1:1、dump 长度是否覆盖最坏情况、缓冲满/进程被杀丢多少——三个数字写进用法 | 抓到的比实际的少，且看不出来 |
| I6 | **落盘自证（flush）** | 每条记录一次写盘；周期 flush 要能关；用**计数非零**证明，不用"日志文件存在"证明 | 短命进程/单帧被抓成"零调用" |
| I7 | **拦截面** | 覆盖 = **静态导入表 ∪ 动态解析**；动态解析的每次结果单独记，并记下指针落在哪个模块 | 拿到函数指针就以为能看见调用 |
| I8 | **窗口/帧边界** | 逐帧比较前先证明**两边日志里都有帧标记**（swap/帧事件）；没有边界的日志只能整段比 | 逐帧比的是对齐假象 |
| I9 | **可开窗** | trace 类仪器必须能按 step/请求区间门控 | 全量 trace 到 GB 级 = 没有仪器 |
| I10 | **簿记配对** | 仪器自己维护的对象表要有删除事件 | 只增不减的簿记会 dump 已释放内存，产出成百上千条**假差异** |
| I11 | **驱动类阳性对照** | 能"发命令"的仪器（合成消息/注入/模拟输入）先跑一个**已知必然生效**的最小动作 | 没反应时分不清是对象坏还是通道不通 |
| I12 | **单位与坐标系** | 用法里注明输出单位、坐标系、与被测进程 DPI awareness 的关系；比例按**抓图尺寸**算 | 物理像素被当逻辑像素，点击按错误倍数偏移 |
| I13 | **修好后重跑历史** | 仪器口径一变，基于它的旧结论全部作废重算；新旧不混在一张表里 | 两个口径的数是同一张表的行 |
| I14 | **便宜指标排序 + 贵指标裁决** | 先用便宜指标（字节相同率、位移）预排，再对前几名算指令级相似度 | 便宜指标直接下结论会假阴性 |
| I15 | **坐标系统计写清分子分母** | 跨两个坐标系做覆盖率必须说明分子来自哪边、分母来自哪边，并做一个**会崩的对照**（把对象放到绝不可能匹配的位置，数字必须掉到 0） | 分子分母取自不同坐标系，覆盖率虚高并被当成"已收敛" |
| I16 | **哨兵值检查** | 凡「恒 0 / 恒空 / 恒常量」先查哨兵与过滤条件 | 负值被当哨兵滤掉，结果恒 0 |
| I17 | **判据的度量必须匹配机制** | 先问"这套机制里哪些字节必然不同"（地址、指针、重定位），排除后再比 | 把"同码"判成"有差距"，进而推出"链接了不同单元" |
| I18 | **写回执 ≠ 生效** | 每个写操作后用**独立读接口**复验（挂断点→列断点、暂停→读状态、写值→读回）；不可复验的写操作按失败处理 | 接口报 "success" 但目标状态没变 |
| I19 | **控制面失效 → 改持久化状态** | 写操作不可复验时，改组件自己的持久化格式离线写入，重启后只读确认（§5） | 继续在协议层加补丁：几百次往返仍没挂完 |
| I20 | **边界来自轨迹事件，不是人工计数** | 用轨迹自带的阶段标记切段（首次 step / 首个 swap / 结束事件）；人工 limit 只作临时手段，且必须在用法里注明「limit 是猜的」 | 人工计数漂移后，判据退化成对常数的拟合 |
| I21 | **量化下限：判据容差 ≥ oracle 的存储精度** | 先量 oracle 自己存成什么精度：float32 的 ulp 随幅值变（`\|p\|≈18` 时 1 ulp=1.9e-6）、定点的一个 LSB、采样的一个间隔。**容差低于步长时判据没有意义**——要么按 ulp/相对容差比，要么先证明实现落在同一精度桶。A/A 地板为 0 也不代表可以把容差压得更小：重复同一记录只证明确定性，不证明精度 | 把 1 ulp 的量化差写成缺陷；或反过来，把触到步长的真差异当噪声放过 |
| I22 | **时间与状态字段** | 每条记录带 `t / state / elapsed`（状态机另带 score 与 margin）；计数类指标先证明它与时间/帧无关——固定 wall-clock 窗口的帧数会浮动（同一命令两跑总调用差 3.6%、中位比值 1.0097），此时判据取**集合**不取计数 | 把「跑久一点」当收敛，或把帧数差写成行为差 |
| I23 | **观测单位一致** | 快照 / 表格必须写「调用点 / 函数入口 / 行 / 帧」；跨单位的数字不比较 | 649/1012（调用点）与 166/361（入口）被当成同一张表的两个数 |

**放弃条件**：当一台仪器的准备成本超过它要回答的问题时，**换尺度**，不要换更硬的仪器。为拿一个定时器参数上调试器、被无关模块的加载事件反复打断，不如用「屏幕小块按固定间隔采样、统计画面变化率」——三行代码就能回答"渲染是按需重绘还是固定 tick"。

## 2. 判据取谁：副作用 oracle > 日志/内存 > 视觉

1. **副作用 oracle** —— 被测系统自己写出的状态：存档、配置、数据库、返回码、退出码。判断「这一关是否通过」读它自己写进存档的进度字段，比识别结算页稳得多，且完全不需要图像处理。
2. **日志 / 内存** —— 代理抓到的调用序列、内部字段转储。信息最全，但必须先过 A/A 与覆盖边界。
3. **视觉 / 听感** —— 像素、波形。只给「输出等价」，还受缩放、遮挡、混音影响；前两层够用时优先前两层，用这层时在结论里标尺度。

抓差分序列时四条硬纪律：

- **oracle 有状态**（对象在它堆上分配、宿主保存这些指针）→ 必须同时记录**返回值**，否则第二条调用就没法把指针翻译成自己实现的指针。
- **一条真实调用序列就是回归语料**：比「实机再点一遍」便宜一个数量级，还能把崩溃离线复现到第几条调用。
- **比首个分歧，不是一致率**：99% 一致而第一条错，后面全是垃圾。
- **报定位，不只报计数**：序列类比对一次给出「长度差 + 首个分歧下标 + 该下标两侧取值」。只给 `mismatches=N` 等于把定位留给下一个人；**长度差往往直接点名缺的是哪个元素**（`bodies COUNT a=45 b=44` 比后面 26 条逐项差更快指向「少一个 body」）。

选题时反过来用：**先问「这个结论能不能由被测系统自己写出来」**——能写的话，整条仪器链都可以省掉。

## 3. 置信度分级

同一套流程对不同问题给出的确信度不同。报结论前先标**尺度**，再谈**多高**——同一对实现完全可能「返回值全同、波形全同、字节不同」。

| 尺度 | 可信度 | 成立条件 |
|---|---|---|
| 崩没崩 / ABI 对不对 | 高（可证伪） | 有**能产生反例的入口**：探针、抓包、把原二进制加载起来。读代码不产生反例 |
| 调用序 / 返回值 | 高（可证伪） | **口径固定**：比的是调用序列；指针返回值要先扣掉地板 |
| 状态数值 | 中（可量化） | 连**容差**和**首个分歧**（step / 字段 / 双方取值）一起报；只报一致率等于把信息扔掉 |
| 输出（波形 / 画面 / 字节） | 低（只能逼近） | 分窗比，不报整段均值；必须说明它**不等于内部逐位** |

- 「崩没崩 / ABI」一次反例就能定死，所以最先花钱的是**入口**，不是读代码。
- 「调用序 / 返回值」只在口径固定时成立：**计数与幅度、整段与分窗会给出相反结论**。
- 「输出一致」不可证：`corr=0.9999` 说的是「混音后波形重合」，中间隔着共享模式重采样——没证明的是哪一层，要写出来。

**桩 / 替身的分级**：桩 harness 返回 plausible 常量只证明**入口齐备**，档次是 `L2-A`（ABI 层），不得升格为行为等价。

## 4. 覆盖边界写法模板

用法里直接抄：

```
覆盖：<函数/字段/事件的集合>；判据：<PASS 条件>（比对类再加：长度差 / 首个分歧下标 / 两侧取值）
边界：看不见 <列表>（原因：<静态导入才有 / 需要符号 / 采样间隔>）；
      地板：A/A <数字>（<输入>、<oracle>、<次数>）；量化步长 <数值/规则>（记录精度）
失效：<上游版本> 变更后重跑 <自检命令>
```

## 5. 控制面失效时：改持久化状态，不改命令通道

当自动化接口的写操作静默失效（I18），**找这个组件的持久化状态文件**——命令拼法再复杂也救不了失效的通道：

- 断点/书签/注释 → 调试器的模块库文件。
- 配置/布局 → 组件的 ini/JSON。
- 会话状态 → 存档/缓存。

判据：**离线写入 → 重启组件 → 用只读接口确认它按新状态运行**。这条路可版本化、可审查、一次写几十条；坏处是写错时组件可能不认——先备份原文件，先用 1 条做最小验证。

配套纪律：命中后用「记录并继续」的模式（写日志 + 自动继续）——一次人工操作变成整段对象序列；「停止型断点 + 逐次读内存」把每次命中都变成一次人工注意力和一次往返。
