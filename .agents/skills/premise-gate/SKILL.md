# Premise Gate

范围已知时计划先于事实；来源不可信时**事实先于计划**。本 skill 管后者：先判这个任务现在能不能开工，判完再谈怎么写、怎么记。

**核心断言**：代码什么时候写都行，每段代码落进四条**归宿**之一——进台账、进 plan、升成 `tools/` 下的仪器、进垃圾桶。四者之外的代码是借债。

## 0. 闸门：先判，再写

只在四种情形过闸：代码来源不可信（反编译 / 遗留 bin / 无文档 SDK）、范围未知写不出验收标准、任务前提是一条待验证的机制断言、靠踩坑记录推进。范围已知 → 直接写验收标准 + plan；只是查资料 → 直接查；bug 稳定可复现 → 先复现再改。

开工前判一次，落三态之一，并写下一句理由：

| 判定 | 条件 | 下一步 |
|---|---|---|
| **直接做** | 关键前提已到 L2 以上，判据能写成二值命令 | 写验收标准 + plan |
| **改造后做** | 前提可证但未证，或判据不是二值的 | 列改造项（造 oracle / 缩状态空间 / 换判据 / 切片），改完回到闸门 |
| **拒绝** | 没有 oracle 且无法构造，或答案只能靠主观判断 | 写明缺什么、要谁补、改造成本 |

「差不多能行」不算通过：理由必须指到具体前提或具体判据。开工前与收尾各扫一遍 `references/lessons.md` 的症状列；归因卡住时按分区对号。

## 1. 改造：把不可判改成可判

**五问**，逐条回答，任一为否就先改造：多项式时间有解吗？状态空间有限吗？反馈几秒？判据直接吗？能切片并行吗？

每问的判法、五项任务表、A–D 分级与选路：`references/difficulty.md`。

## 2. 四步循环（改造后执行）

一轮探测 = 一次可落账的最小单元。四步走完才算一轮，台账必须多一行。

### 2.1 Claim

写**三行**：

1. **假设**：一句，可判真假；附置信度与「万一错了，最可能错在哪」。
2. **两个互斥预测**：假设成立时看到什么、不成立时看到什么。
3. **机器判据**：命令 + PASS 条件。

三行写不齐就先不跑。

**门**：这轮回答 plan 的哪一行（Open Question / 风险 / 写不出验收标准的任务）？**完成判据**：台账里已有一行 `待证`，且三行都能判真假。

### 2.2 Probe

| 约束 | 做法 |
|---|---|
| 标记 | 独立目录/命名空间 + 等价编译隔离（独立 asmdef / package / 入口）；文件名与提交前缀带 `probe` |
| 一次性 | 一条脚本：读 → 打印 → 删。状态放内存（持久化本身常是被测对象）；抽象、测试、错误处理全略 |
| 只读正式路径 | 生产代码、共享配置、源数据只读；第三方 vendor 副本可改，每处标 `altered (Fxxx)` 并与 oracle 对拍；oracle 本体只读 |
| 环境干净 | 先清掉：单实例应用的旧进程、被独占的设备、上一轮残留进程——否则测到的是**残留状态**，它的症状与被测对象真有 bug 一模一样 |
| 一次一个变量 | 一轮只变一个变量，结论才归因得到 |

**能操作不等于知道在哪。** 动鼠标/注内存之前先做状态判定（画面锚点、状态机），判定不出来时显式返回 `unknown`。

**oracle 可观测时先差分，后推断。** 有参考实现（原版二进制 / 旧服务 / 影子流量）能对同一输入给输出时，第一步把它的 I/O 抓下来，而不是读反编译猜布局（武器清单见 §6，仪器做法见 `references/instruments.md`）。

**完成判据**：两个预测灭掉一个（两个都灭也算——假设错，另起一行 `待证`）；输出能贴进台账的出处列。

### 2.3 Record

往台账（§8 的路径）追加一行，先落账再写代码。同会话多个探测各落各账。

**完成判据**：出处能被另一个人照着重放出同一结论——路径+行号 / 命令 / 观察步骤。

### 2.4 Promote

| 结论 | 动作 |
|---|---|
| 成立 | 折叠进正式代码 + plan 追加任务（`依据：F01`） |
| 不成立 | 台账划掉该行 + 原型回滚 |
| 仍不确定 | 记 `待证`，写明下一轮要区分的两个假设 |

任务行带 `依据：F01, F02`；依据缺失或指向不存在的 id → 拒绝开工（台账已漂移，先修台账）。原型存 `probe/<project>` 分支并在 plan 写 `原型：probe/<project>@<sha>`；仓库已有 gitignored 的 `work/` 时放那里。提交前缀跟仓库 `git log`，没有约定时用 `probe(<scope>):`。plan/todo 放仓库约定的计划位置（有约定就用它的；没有时用 `docs/plans/`）。升成仪器时 docstring 备齐四件事（命令 / 判据 / 覆盖边界 / 失效条件），见 `references/instruments.md` §0。

**完成判据**：四条归宿各有落点——台账行状态已更新、plan 有依据行、脚本已升仪器或已删、原型已定位（分支或 `work/`）。

## 3. 停止条件

只有三条，触发即停：

1. 下一步不可逆（删源资产、改存档/缓存格式、覆盖共享资源、改生产数据）→ 要批准。
2. 唯一依据是 L1 → 先补 L2+。
3. 已授权任务的依据被证伪 → 重评该任务及全部下游。

仪器不可用（地板无穷大、抓不到目标状态）时换仪器或换尺度，继续。

## 4. 证据等级

| 等级 | 来源 | 可授权 | 不可授权 |
|---|---|---|---|
| L1 | 反编译源码（dnSpy/ILSpy/jadx/apktool 产出） | 探测方向 | 实施、验收、spec 里的「事实」 |
| L2 | 字节码/指令、符号表、反射或类型 dump；自有解析器对目标数据的 dump；代理/转发层抓到的真实调用序列（实参+返回值） | 该符号或该数据集范围内的实施 | 跨模块行为推断；状态机/时序行为（调用序列不带时间与异步完成信息） |
| L3 | 日志、断点、profiler、单测断言 | 实施 + 技术验收 | 玩家/用户可见行为 |
| L4 | 实机观察；独立第二实现输出一致；同一条真实序列重放逐条一致 | 验收、写进 AGENTS.md、回归基准 | — |

**取最低可信来源**，不取最高。一条事实混了两种来源就拆成两行。L1 与 L4 冲突时以 L4 为准，并给 L1 那行加勘误。

## 5. 报结论

任何「有差异 / 无差异」的结论同时给**四件套**：**地板**（同输入同 oracle 跑两遍的差值）、**边界**（仪器看不见什么）、**判据形态**（个数还是幅度）、**尺度**（崩没崩 / 调用序 / 状态数值 / 输出）。四项齐了才算结论。

两条硬规则：计数类判据先做 A/A，地板内的计数不构成证据；输出层一致（`corr=0.9999`、像素 `mean|Δ|`）只覆盖最外层，不证明内部逐位。

细节（自证清单、判据取谁、置信度分级、覆盖边界模板、控制面失效）在 `references/instruments.md`。

## 6. 三种归因武器

| 武器 | 前提 | 关键规则 |
|---|---|---|
| **差分 oracle** | 参考实现可运行、输入可完整记录 | 抓取层透明（代理占位，实参/返回值/指针内存全记，栈与寄存器不动）；只认**首个分歧**；输入记不全（时间戳/异步/线程调度）就改同脚本实机对拍 |
| **逐文件二分** | 两棵树都能独立构建 | 先对齐位移再比相似度（「同一位移」是要验证的假设）；每轮换一半文件重编重跑；`diff` 报的差异可能全无行为影响 |
| **修订夹逼** | 上游有修订史 | 算与重定位无关的逐函数相似度，找**跳变点**，不看单调漂移；全不跳 ⇒ 原版带本地补丁或来自别的分支；残差成簇 = 本地补丁，复原后判据是归零 + 一条负例 |

## 7. 偏离与回流

1. **边做边改是默认节奏。** 改动只许追加：plan 加一条变更记录（日期 / 依据 fact id / 受影响任务 / 新决定），已批准条目原样留着。
2. **依据被推翻** → 走停止条件 3：台账勘误 → plan 追加变更 → 重评下游 → 继续。
3. **中途或末尾追加需求** → 先写进计划目录的 `backlog.md`，当前任务继续；只有与当前任务争用同一接口或同一份数据（做完要返工）才插入，并按第 1 条记变更。
4. **需求不明确** → 先做一次会话内可运行、可展示的最小竖切，把它当探测：结论进台账，再写 plan。plan 跟随代码。

## 8. 台账

`docs/facts.md`（路径可用 `FACTS_FILE` 覆盖），只增不减。台账寿命永久，不混进计划文件（那里是周级的）。

| id | claim | 等级 | 出处 | 状态 | 影响 |
|---|---|---|---|---|---|
| F01 | 谱面时间戳是毫秒整数，不是秒 | L3 | `chart_parser.py` 实读 + 一条运行时日志 | 已证 | T8 |
| F02 | ~~离线包不含音频~~ | L2 | `unpack.py` 不递归 | **已证伪** | T2 |

- 等级列只允许 `L1`–`L4`；细分用后缀（`L2-A` = 只覆盖 ABI 层）或复合（`L2/L4`）并在行内说明；未定级写 `待定`。
- 状态只有四种：`待证` / `已证` / `已证伪` / `过期`。上游变更（游戏更新、依赖升级、数据源换代）后把受影响模块的 L3/L4 行批量置 `过期`——结论会腐烂。
- 出处可重放：路径+行号 / 命令 / 观察步骤。
- 证伪：旧行划删除线并改状态，另起一行写勘误。行内改（状态流转、删除线）是唯一改法。

校验：`scripts/append-only-check.sh` 守「只增不减」（fact id 集合、`- [x]` 行数），可作 pre-commit。POSIX shell 里 `bash scripts/append-only-check.sh`；`bash` 解析到 WSL 启动器时（Windows）改用 Git Bash 全路径。主干不留探测痕迹：`git log --oneline --grep '^probe' <主干分支>` 为空。

## 9. 项目适配

这套规则落到具体仓库时，把**落点**写进那个仓库的 `AGENTS.md`（或它已有的 plan / 交接文件）：台账路径、计划文件、一次性探测目录、仪器目录、只读 oracle、机器判据命令、采集/控制面。

**本机事实放项目仓库**：解释器与工具的绝对路径、SDK 安装位置、服务名、账号——这些换机器就失效，在 `AGENTS.md` 里记一次即可。本 skill 只写相对约定与判据，保证换项目、换机器都原样可用。

**计划目录是仓库约定**：`tasks/plan.md` + `tasks/todo.md`（agent-skills 家族的约定）、`docs/plans/` 都算，本 skill 不另立一套；校验脚本用 `FACTS_FILE` / `PLAN_GLOBS` 指向该仓库的实际路径。
