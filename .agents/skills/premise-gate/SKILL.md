# Premise Gate

范围已知时计划先于事实；来源不可信时**事实先于计划**。本 skill 管后者：先判这个任务现在能不能开工，判完再谈怎么写、怎么记。

**核心断言**：每段代码落进四条**归宿**之一——进台账、进 plan、升成 `tools/` 下的仪器、进垃圾桶。四者之外的代码是借债。

## 0. 闸门：先判，再写

先按任务形态分流：

| 任务形态 | 动作 |
|---|---|
| 纯文档 / 注释 / 计划整理 | 直接改；不预注册、不占 fact |
| 只是查资料 | 直接查；结论要落账时再按 §2 |
| bug 稳定可复现 | 先复现再改；复现命令进台账 |
| GUI 输入自动化 / 拖拽验证 | 先造**状态回读 + 坐标标定图**；标定 claim 过闸后再写行为判据（`references/instruments.md` §0.7） |
| 来源不可信 / 二值判据写不出 / 机制断言未证 / 靠踩坑推进 | 过下面的闸门 |

`来源不可信` 包括反编译产物、遗留二进制、无文档 SDK、只能靠观察行为的第三方实现。

开工前判一次，落三态之一，并写下一句理由：

| 判定 | 条件 | 下一步 |
|---|---|---|
| **直接做** | 关键前提有 L2+ 证据且判据是二值的（授权范围见 §4） | 写验收标准 + plan |
| **改造后做** | 前提可证但未证，或判据不是二值的 | 列改造项（造 oracle / 缩状态空间 / 换判据 / 切片），改完回到闸门 |
| **拒绝** | 没有 oracle 且无法构造，或答案只能靠主观判断 | 写明缺什么、要谁补、改造成本 |

「差不多能行」不算通过：理由必须指到具体前提或具体判据。判定落进 plan 头部：`gate: passed | mode=<直接做/改造后做/拒绝> | oracle=<…> | criteria=<命令> | round=<n> | status=<planned/running/blocked/done> | date=<YYYY-MM-DD>`；续轮只改 `round`/`status`，`oracle` 或 `criteria` 变了才重判。

开工前与收尾各扫一遍 `references/lessons.md` 的症状列；归因卡住时按分区对号。

## 1. 改造：把不可判改成可判

**五问**，逐条回答；否或写不出理由就先改造：多项式时间有解吗？状态空间有限吗？反馈几秒？判据直接吗？能切片并行吗？

改造项：造 oracle / 造**合成契约探针** / 造**状态回读 + 坐标标定图** / 缩状态空间 / 换判据 / 换尺度 / 切片并发 / 压反馈（无头 / 离线 / 子阶段化）。

语料有**结构盲区**（采集层过滤、宿主从未调用）时先造契约探针：固定序列点遍每个入口、两侧各跑一遍。它比补语料便宜，还能抓「跑通但 ABI 错」——录制只证明被观测到的调用。判据与做法见 `references/instruments.md` §0.3。

每问的判法、五项任务表、A–D 分级与选路：`references/difficulty.md`。

## 2. 四步循环（改造后执行）

一轮探测 = 一次可落账的最小单元。四步走完才算一轮，台账必须多一行。

### 2.1 Claim

写**三行**：

1. **假设**：一句可判真假；置信度 高/中/低（定义见 `references/claims.md`）；错了最可能错在 ___。
2. **互斥预测**：成立 → ___；不成立 → ___；两者要能被同一命令区分。
3. **机器判据**：`<command>` → `PASS=<condition>`（含地板 / 容差 / 窗口）。

三行写齐才跑。三行可以边读 oracle 边成型（§2.2 的差分取证属于**形成 claim**）；**动生产代码之前**先往台账追加一行 `待证`（预注册：假设 + 判据）。Probe 结束只回写这一行；claim 在探测中改了，改这一行，不另起重复行。探测中派生的新 claim（先证入口、再证状态切换）另起一行 `待证`；同一 claim 的新证据只回写原行。

claim 是**普查**（覆盖表 / 通过数）、**性能 / 规模**或**仪器 / 输入仪器**时，三行各换一套写法；置信度分级与 `快照` 行同在 `references/claims.md`。

**门**：这轮回答 plan 的哪一行（Open Question / 风险 / 写不出验收标准的任务）？**完成判据**：动生产代码之前，台账里已有预注册的 `待证` 行（假设 + 判据），且三行都能判真假。

### 2.2 Probe

| 约束 | 做法 |
|---|---|
| 标记 | 独立目录/命名空间 + 等价编译隔离（独立 asmdef / package / 入口）；文件名与提交前缀带 `probe` |
| 一次性 | 一条脚本：读 → 打印。状态放内存（持久化本身常是被测对象）；抽象、测试、错误处理全略。台账要引用的探针留档：升 `tools/`（带 `references/instruments.md` §0 的四件事），或留在 gitignored 的探测目录，并在台账行写**路径 + 生成命令 + 输入** |
| 只读正式路径 | 生产代码、共享配置、源数据只读；第三方 vendor 副本可改，每处标 `altered (Fxxx)` 并与 oracle 对拍；oracle 本体只读 |
| 共享资源 | 默认音频端点、系统混音器、玩家存档/缓存/配置按生产数据处理：能隔离就隔离（独立 profile、私有桌面、虚拟音频设备），不能隔离就备份并在 `finally` 恢复；恢复命令写进台账。私有桌面只隔离窗口/输入，音频另行隔离 |
| 环境干净 | 先清掉：单实例应用的旧进程、被独占的设备、上一轮残留进程——**残留状态**的症状与被测对象真有 bug 一模一样 |
| 一次一个变量 | 一轮只变一个变量，结论才归因得到 |

**能操作不等于知道在哪。** 动鼠标/注内存之前先做状态判定：**优先读进程内状态字段 / 日志 / API，屏幕锚点只作最后兜底；固定延时不是状态判定**。判定不出来时显式返回 `unknown`。**驱动同理**：能调状态机 / 命令入口时，驱动走状态机 / 命令入口；输入自动化只用于证明输入通道与光标驱动的玩法路径。

**输入自动化另加两件套。** ① **状态回读**：每步一份小 digest（对象 id → 位置/事件），控制回路只读这一份；回路里解析全量日志或截图会把「鼠标没动」伪装成「对象没反应」。② **坐标标定图**：截客户区，画刚体编号 + 世界坐标、目标十字、预计轨迹；标注点必须**压住实际对象**，屏幕 y 与 GL/世界 y 的朝向、DPI、客户区物理像素写进标定。标定未过不写拖动代码；细节见 `references/instruments.md` §0.7。

**输入通道被引擎输入循环拥有时，状态字段留给引擎。** 每帧被输入层刷新的目标/按键/光标字段（例：交互对象上的 target/active/button）从外部写会与输入循环竞态；改走进程内 API/代理注入（同一物理世界直接施力或设速度）或调用引擎自己的 update。状态机/菜单切换是异步的：`level state` 先出现不代表菜单已关；等 0.5–1 s 并**复查 level + menu + 控制器已 arm** 再开始动作（`references/instruments.md` I26）。

**oracle 可观测时先差分，后推断。** 有参考实现（原版二进制 / 旧服务 / 影子流量）能对同一输入给输出时，第一步把它的 I/O 抓下来（武器清单见 §6，仪器做法见 `references/instruments.md`）。

**未知签名 / 布局先做最小探测。** 错误 ABI 不必然崩：cdecl 的多余参数由调用方清理、静默忽略，写坏的是对象头部，症状延迟到无关调用才出现。用「逐参数 / 逐字节置 1 + 最小可崩调用」定槽位，再拿反汇编确认；「跑通一次」不构成签名正确的证据。

**完成判据**：两个预测灭掉一个（两个都灭也算——假设错，另起一行 `待证`）；输出能贴进台账的出处列。

### 2.3 Record

2.1 已预注册 `待证` 行；Probe 结束后**更新这一行**：状态改 `已证（行为）` / `已证（机制）` / `已证伪`（限定见 §8），补可重放的出处（路径+行号 / 命令 / 观察步骤 / A/A 地板）。同一 claim 的重复探测不另起新行。

**完成判据**：出处能被另一个人照着重放出同一结论；引用探针时按 §2.2 的归宿写全路径与生成命令。

### 2.4 Promote

| 结论 | 动作 |
|---|---|
| 成立 | 折叠进正式代码 + plan 追加任务（`依据：F01`） |
| 不成立 | 台账划掉该行 + 原型回滚 |
| 仍不确定 | 记 `待证`，写明下一轮要区分的两个假设 |

任务行带 `依据：F01, F02`；依据缺失或指向不存在的 id → 拒绝开工（台账已漂移，先修台账）。原型存 `probe/<project>` 分支并在 plan 写 `原型：probe/<project>@<sha>`；仓库已有 gitignored 的 `work/` 时放那里。提交前缀跟仓库 `git log`，没有约定时用 `probe(<scope>):`。plan/todo 放仓库约定的计划位置（有约定就用它的；没有时用 `docs/plans/`）。升成仪器时 docstring 备齐四件事（命令 / 判据 / 覆盖边界 / 失效条件），见 `references/instruments.md` §0；提交前跑一次正例并把输出写进台账。

**完成判据**：四条归宿各有落点——台账行状态已更新、plan 有依据行、脚本已升仪器或已删、原型已定位（分支或 `work/`）。

## 3. 停止条件

只有三条，触发即停：

1. 下一步不可逆（删源资产、改存档/缓存格式、覆盖共享资源、改生产数据、改系统默认音频端点/混音器）→ 要批准。
2. 唯一依据是 L1 → 先补 L2+。
3. 已授权任务的依据被证伪 → 重评该任务及全部下游。

仪器不可用（地板无穷大、抓不到目标状态）时换仪器或换尺度，继续。

## 4. 证据等级

| 等级 | 来源 | 可授权 | 不可授权 |
|---|---|---|---|
| L1 | 反编译源码（dnSpy/ILSpy/jadx/apktool 产出） | 探测方向 | 实施、验收、spec 里的「事实」 |
| L2 | 字节码/指令、符号表、反射或类型 dump；自有解析器对目标数据的 dump；代理/转发层抓到的真实调用序列（实参+返回值） | 该符号或该数据集范围内的实施；范围 = 被观测的输入/关卡集合，换输入要新观测 | 跨模块行为推断；状态机/时序行为（调用序列不带时间与异步完成信息）；未观测输入上的泛化 |
| L3 | 日志、断点、profiler、单测断言 | 实施 + 技术验收 | 玩家/用户可见行为 |
| L4 | 实机观察；独立第二实现输出一致；同一条真实序列重放逐条一致 | 验收、写进 AGENTS.md、回归基准 | — |

**L2 只授权被观测范围**：行为、时序、输出等价另要 L3/L4 或仪器判据。**取最低可信来源**，不取最高。一条事实混了两种来源就拆成两行。L1 与 L4 冲突时以 L4 为准，并给 L1 那行加勘误。

## 5. 报结论

任何「有差异 / 无差异」的结论先填**四件套**，缺一不算结论：

- **地板**：两次**独立采集**的差值 = ___（量化下限见 `references/instruments.md` I21）
- **边界**：仪器看不见 ___
- **判据形态**：个数 / 幅度 / 逐位 / 几何（bbox / 顶点 / 边方向）
- **尺度**：崩溃 / 调用序 / 状态数值 / 输出（每个数字带观测单位，I23）

- **A/A 要独立**：同一份日志或同一帧重放两次只证明解析确定；地板要两次独立采集（I24）。动画 / 悬停 / 物理运动会随时间变，先钉同一瞬时态（时刻、输入、状态字段），静态项与动态项分开报。
- **状态 / 计数 claim 的地板** = 两次独立启动同一脚本的同一量（如 `steps=1266` vs `1266`、同一对象集合）；启动抖动使计数不稳时，地板取集合或区间，不取单点。
- **尺度不外推**：存在性（集合 / 调用序）、数量（计数 / 幅度）、数值（逐位 / 容差）是同一件事的不同侧面——集合相等不说明逐位一致；固定 wall-clock 窗口的计数不可复现时判据取集合。三个尺度分开写。
- **输出层只覆盖最外层**：`corr=0.9999`、像素 `mean|Δ|` 证明的是混音/渲染后的重合；内部逐位另证。

几何层（I17）、输入自动化（I25）、物理 vs UI（I26）、A/B 实现级别（I27）、采集失败分桶（I28）：`references/instruments.md`。

## 6. 三种归因武器

| 武器 | 前提 | 关键规则 |
|---|---|---|
| **差分 oracle** | 参考实现可运行、输入可完整记录 | 抓取层透明（代理占位，实参/返回值/指针内存全记，栈与寄存器不动）；只认**首个分歧**；输入记不全（时间戳/异步/线程调度）就改同脚本实机对拍 |
| **逐文件二分** | 两棵树都能独立构建 | 先对齐位移再比相似度（「同一位移」是要验证的假设）；每轮换一半文件重编重跑；`diff` 报的差异可能全无行为影响 |
| **修订夹逼** | 上游有修订史 | 算与重定位无关的逐函数相似度，找**跳变点**，不看单调漂移；全不跳 ⇒ 原版带本地补丁或来自别的分支；残差成簇 = 本地补丁，复原后判据是归零 + 一条负例 |

## 7. 偏离与回流

1. **边做边改是默认节奏。** 改动只许追加：plan 加一条变更记录（日期 / 依据 fact id / 受影响任务 / 新决定），已批准条目原样留着。
2. **依据被推翻** → 走停止条件 3：台账勘误 → plan 追加变更 → 重评下游 → 继续。
3. **中途或末尾追加需求** → 先写进计划目录的 `backlog.md`，当前任务继续；只有与当前任务争用同一接口或同一份数据（做完要返工）才插入，并按第 1 条记变更。**暂缓 ≠ 取消**：每条写「为什么暂缓 + 回流条件」，回流时先补 oracle 与二值判据再进队列。四类典型：

   | 类型 | 例子 | 回流条件 |
   |---|---|---|
   | 超出验收口径 | 逐位 PCM（合同只要求「差分」） | 口径改判，或用户明确要求逐位 |
   | 已被新链路取代 | 全量 oracle 采集（按需取样已覆盖） | 需要跨层同一时间线时 |
   | 路线冻结 | 旧实现路线留作对照物 | 新路线在某判据上覆盖不到 |
   | 不可判（无 oracle） | 1 ulp 残差 | 有了更细的量化下限或合成扫描 |

4. **需求不明确** → 先做一次会话内可运行、可展示的最小竖切，把它当探测：结论进台账，再写 plan。plan 跟随代码。

## 8. 台账

`docs/facts.md`（路径可用 `FACTS_FILE` 覆盖），只增不减。台账寿命永久，不混进计划文件（那里是周级的）。

| id | claim | 等级 | 出处 | 状态 | 影响 |
|---|---|---|---|---|---|
| F01 | 谱面时间戳是毫秒整数，不是秒 | L3 | `chart_parser.py` 实读 + 一条运行时日志 | 已证（行为） | T8 |
| F02 | ~~离线包不含音频~~ | L2 | `unpack.py` 不递归 | **已证伪** | T2 |

- 等级列只允许 `L1`–`L4`；细分用后缀（`L2-A` = 只覆盖 ABI 层）或复合（`L2/L4`）并在行内说明；未定级写 `待定`。
- 状态五种：`待证` / `已证` / `已证伪` / `过期` / `快照`。上游变更（游戏更新、依赖升级、数据源换代）后把受影响模块的 L3/L4 行批量置 `过期`——结论会腐烂。
- **一行一 claim**：机制（为什么/能否）与覆盖（多少/哪些）拆行（`references/claims.md`）。
- `已证` 带限定：**`已证（行为）`** = 输出/调用序在 oracle 下对齐；**`已证（机制）`** = 还解释了**为什么**（反汇编/源码证据，或可复现的机制实验）。只有行为对齐时，claim 里写「机制未归因」——否则读者会把「已证」读成「知道原因」。
- `快照` = 覆盖表 / 通过数一类**随构建变化**的测量：行内带构建指纹与四条自检钩子，规则见 `references/claims.md`；同一范围出新快照就把旧行置 `过期`。
- 出处可重放：路径+行号 / 命令 / 观察步骤。
- 证伪：旧行划删除线并改状态，另起一行写勘误。行内改（状态流转、删除线）是唯一改法。
- 追加落盘自证：台账用二进制或显式换行追加（文本模式读文件会把 CRLF/LF 静默转换）；写完看 `git diff --numstat`——只许「只增行」（如 `2 0`），出现对称的删行数就是整文件重写，回滚重写再提交。

校验：在目标仓库根目录运行**本 skill 自带**的 `scripts/append-only-check.sh`（用法与退出码见脚本头部；默认检查索引，未暂存时退出 2，`--worktree` 检查工作树）。目标仓库没有该脚本时，至少跑 `git diff --numstat -- <facts> <plans>`（只许 `N 0`）和 fact-id 集合差（旧 id 全在、新增 id 无重复）。POSIX shell 里 `bash <skill>/scripts/append-only-check.sh`；`bash` 解析到 WSL 启动器时（Windows）改用 Git Bash 全路径。主干不留探测痕迹：`git log --oneline --grep '^probe' <主干分支>` 为空。

## 9. 项目适配

这套规则落到具体仓库时，把**落点**写进那个仓库的 `AGENTS.md`（或它已有的 plan / 交接文件）：台账路径、计划文件、一次性探测目录、仪器目录、只读 oracle、机器判据命令、采集/控制面。

**本机事实放项目仓库**：解释器与工具的绝对路径、SDK 安装位置、服务名、账号——这些换机器就失效，在 `AGENTS.md` 里记一次即可。本 skill 只写相对约定与判据，保证换项目、换机器都原样可用。

**计划目录是仓库约定**：`tasks/plan.md` + `tasks/todo.md`（agent-skills 家族的约定）、`docs/plans/` 都算，本 skill 不另立一套；校验脚本用 `FACTS_FILE` / `PLAN_GLOBS` 指向该仓库的实际路径。

**共享资源写进项目约定**：存档/音频端点/系统设置的**隔离方式**写进 `AGENTS.md`；每轮探测的**恢复命令**进台账（§2.2）；私有桌面只隔离窗口/输入，不等于音频隔离。
